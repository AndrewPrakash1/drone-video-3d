# SIH26158 mapping

Official statement: georeferenced, metrically accurate 3D from a **single** UAV video pass (NTRO / Robotics and Drones). Judges need visualization, measurement, and analysis — not a pretty unscaled mesh.

## Inputs

Mandatory: 1080p/4K video, GPS, flight metadata.
Optional: IMU, barometric altitude, camera intrinsics, RTK/PPK.

CSV schema used here:

```
timestamp,lat,lon,alt,heading,speed,hdop,rtk
```

`timestamp` is seconds from video start.

## Pipeline in this repo

1. Sync telemetry to frames.
2. Score frames (sharpness, ORB count, texture, exposure, redundancy) and keep ~2–5 fps.
3. Adaptive layer: down-weight GPS when HDOP/jumps are bad; prefer triangulation when overlap exists; nadir unprojection when a single pass is too sparse.
4. Fast path: VGGT on CUDA (chunked, GPS-aligned) or CPU geometry.
5. Accuracy path: COLMAP SfM fused into the same live point cloud when `colmap` is on PATH.
6. ENU georeferencing from the first reliable GPS sample.
7. Open3D Poisson mesh when the cloud is dense enough.
8. Confidence bands (high / medium / low).
9. Metric UI: measure two points vs a known length (proxy rooftop = 20.0 m, tolerance max(1 m, 5%)).

## Eight official challenges

| Challenge | OnePass response |
|---|---|
| Limited viewing angles | Sparse AI/nadir path; COLMAP only with overlap |
| Blur / compression | Drop low Laplacian frames |
| Illumination | Exposure gate |
| Dynamic objects | Ratio-test matches / short tracks |
| GPS noise | Reliability score |
| Near-real-time | Chunked SSE updates |
| Occlusions | Low confidence, no fake facades |
| Metric without GCPs | GPS scale + reference length check |
